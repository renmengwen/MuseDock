# 白板制作流程 Agent 化改造：自然语言意图理解 + 流式对话 UI

## 背景与目标

现状：白板制作流程中用户自由文本消息由正则路由（`whiteboardWorkflows.js:181-192`）硬编码猜测意图，"……为什么有边框？重新生成"这类"提问+指令"被问句正则吞掉，修订静默丢失。本次改造：

1. 消息入口换成 LLM 意图理解（自研轻量层，复用现有 `callTextModel`，不引框架）
2. 助手回复改为流式传输 + 前端打字机效果
3. UI 引入 shadcn 生态聊天组件（官方 chat 组件 + AI Elements）
4. 顺带修复 scene_render 修订无效 bug、支持一次多幕修订

## 一、服务端：激活流式（aiTextModel.js）

- `effectiveStream = false` 改为尊重 `stream` 选项；`readStreamResponse` 增加 `onDelta(textChunk)` 回调，逐块触发
- `callTextModel` 新增 `onDelta` 透传选项；**默认行为不变**（不传 onDelta 的现有调用方零影响）
- 工具调用/JSON 模式仍走非流式

## 二、服务端：意图理解层（新文件 `whiteboard/agentRouter.js`）

`interpretMessage({ message, context, services })` 两段式：

1. **快速意图分类**（非流式，response_format JSON，小 maxTokens）：入参 context 含当前阶段、gate、可用动作、全部幕列表（序号+id+标题+产物状态）、最近失败信息。输出工具化结构：
   - `revise_scenes { sceneIds[], instruction }` — 修改指定幕（从自然语言抽取"1、2、6、7"这类指代）
   - `answer { questionHint }` — 状态问答/一般讨论
   - `revise_plan { instruction }` — 方案级修订（仅制作未启动时）
2. **answer 时二次流式调用**生成接地回答（上下文含真实进度/失败原因，替代现在只会背方案总结的 FAQ），`onDelta` 逐块发出

**安全边界（结构性保证）**：意图层工具集里根本不提供 `approve_media`/`authorize_media_retry`/`start_production`/`regenerate_narration`——模型无法替用户放行产物或授权扣费，这些仍只走审批卡按钮 + 显式 `confirmed:true`。模型输出 sceneIds 需校验合法；模型未配置或调用失败时降级回现有正则路由并提示中文错误。

## 三、服务端：消息分支重写 + 修 bug

- `whiteboardWorkflows.js` 消息分支：删除问句/确认正则三岔（保留"确认…"精确正则→approve），其余走 `interpretMessage`
- 意图分类在 `mutate` 文件锁**之外**执行（先读快照做 context），只把结果应用放锁内，避免长占队列
- `productionWorkflows.act` 的 `revise_media` 支持多幕 `sceneIds[]`：循环写 overrides、删除各幕 lineart/annotations/scenes 缓存、重置后续阶段
- **修复 scene_render 修订无效 bug**：`renderSceneCandidate` 的 inputIdentity 计入 `overrides['scene_render:xxx']`，避免 override 后被 `reuseHistory` 复用旧视频
- 流式通道复用现有任务系统：message action 返回 `202+task_id`，经 `taskContext.emit` 新增 `message_delta` 事件类型（前端已有 SSE 订阅管道）

## 四、前端：聊天 UI 改造（WhiteboardTaskDetail.jsx）

- 引入官方 shadcn chat 组件（纯展示、零 AI SDK 绑定）：`npx shadcn@latest add message-scroller message bubble`，替换手写消息列表（149-176 行）
- 按需引入 AI Elements（shadcn registry，源码进项目，MIT）：`Conversation`（自动滚动/流式容器）、`Task`（制作进度卡）、`Confirmation`（增强现有审批卡 WhiteboardConversationCard）
- 打字机效果：SSE 订阅 `message_delta` 事件流式追加当前助手消息，MessageScroller 负责流式跟随滚动
- **移除"需要修改的分镜"单选下拉**（171-172 行）：幕由模型从自然语言抽取；发送中显示"正在理解你的意图..."

## 五、验证

- 单测（只跑相关文件）：意图路由工具解析（mock callTextModel）、多幕 revise_media 的 overrides/缓存清理、scene_render inputIdentity 含 override、onDelta 流式回调
- 前端构建 + 类型检查；手动验证：发送"1、2、6、7 为什么有边框？重新生成"应触发多幕修订而非 FAQ

## 实施顺序

1. aiTextModel 流式 + onDelta（独立可验证）
2. agentRouter + 消息分支重写 + 多幕修订 + scene_render bug 修复 + 单测
3. SSE message_delta + 前端组件替换 + 打字机
4. 构建验证 + 手动回归

不引入 LangGraph/CopilotKit 运行时依赖；新增组件均为 shadcn CLI 源码分发。
