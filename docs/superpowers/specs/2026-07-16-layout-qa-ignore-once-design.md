# 布局 QA 误报修复与单次忽略设计

## 目标

修复 html-video 布局 QA 将纯文本容器空白区误判为文字遮挡的问题，并允许用户在明确的 `frame_layout_qa_unresolved` 失败下，单次跳过失败帧的布局检查后继续原任务。

## 边界

- 单次忽略只适用于当前恢复计划错误码为 `frame_layout_qa_unresolved` 的任务。
- 不允许忽略白屏、素材缺失、渲染失败、合成失败或最终视觉巡检阻断。
- 不增加全局设置，不永久关闭布局 QA。
- 复用原任务的素材、旁白和 content graph，只重新处理失败帧及其后续渲染、合成和视觉巡检。

## 后端

1. 布局 QA 收集候选文字时，如果带文本锚点的元素自身没有直接文本、且已有后代候选文字，则不再把父容器矩形作为独立文字矩形参与重叠检查。
2. 重试规划器将 `frame_layout_qa_unresolved` 映射到现有 `retry_frame_html`，只丢弃失败帧和后续渲染产物。
3. 现有恢复接口接受可选参数 `ignore_layout_qa_once: true`。后端重新生成最新恢复计划并校验：
   - 当前错误码必须为 `frame_layout_qa_unresolved`；
   - `confirm_plan_code` 必须与最新计划一致；
   - 校验失败返回中文 `400`，不启动恢复任务。
4. 合法的单次忽略仍走现有 `retry_frame_html` 恢复动作，但仅在这一次恢复执行中关闭失败帧的布局 QA；随后继续渲染、合成和最终视觉巡检。
5. 恢复尝试记录保留单次忽略标记，便于错误日志区分普通修复与用户确认后的继续执行。

## 前端

- `CreativeRetryPlan` 仅在恢复计划可重试且错误码为 `frame_layout_qa_unresolved` 时显示次按钮“忽略本次布局警告并继续”。
- 原“修复并重试”按钮保持主按钮样式；忽略按钮使用现有 `shadcn/ui` 次级按钮样式，不引入新颜色或组件。
- 按钮旁显示：“仅跳过本次失败帧的布局检查，后续仍会执行渲染和视觉巡检。”
- 点击忽略按钮后显示“正在忽略布局警告并继续...”，所有恢复按钮同时禁用，防止重复请求。
- 请求失败时恢复可操作状态，并展示后端返回的中文错误；请求成功后沿用现有任务 SSE 订阅和进度更新。

## 验证

- 浏览器布局 QA 用例：纯文本父容器与兄弟文本的矩形相交、实际子级文字不相交时应通过。
- 重试规划器用例：`frame_layout_qa_unresolved` 生成失败帧级 `retry_frame_html` 计划。
- 路由和服务用例：单次忽略只接受目标错误码，并把标记传入恢复执行。
- 前端用例：目标错误码显示按钮、其他错误码不显示、请求期间有中文 loading 和禁用态。
- 运行相关 Node 测试、前端构建和 `git diff --check`。
