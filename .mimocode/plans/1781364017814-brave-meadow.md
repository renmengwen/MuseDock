# Task 1: Scene Spec Domain Service 执行计划

## 任务概述
创建 `server/services/sceneSpec.js` 纯数据逻辑服务，包含场景规格的规范化、验证和编辑功能。

## 当前状态
- Git 分支：dev ✓
- 测试目录：tests/ 已存在
- 现有测试风格：CommonJS + assert，使用 `node tests/test-*.js` 运行

## TDD 执行步骤

### Step 1: 创建失败的测试文件
**文件：** `tests/test-scene-spec.js`

测试内容（来自计划文档）：
- 测试 `normalizeSceneSpec()` 规范化功能
  - version 设为 1
  - scenes 添加 order 和 start 字段
  - duration 保留两位小数
  - 添加 editable.local_tts: true
- 测试 `validateSceneSpec()` 验证功能
  - 有效规格返回 success: true
  - 无效规格返回 success: false，错误信息包含"场景 1"
- 测试 `applySceneSpecEdit()` 编辑功能
  - caption_text: 更新字幕文本，requires_tts: false，requires_render: true
  - narration_text: 更新旁白，requires_tts: true
  - reorder_scenes: 重排场景，重新计算 start 时间

### Step 2: 运行失败的测试
```bash
node tests/test-scene-spec.js
```
预期：失败，因为 `server/services/sceneSpec.js` 不存在

### Step 3: 实现纯数据服务
**文件：** `server/services/sceneSpec.js`

导出函数：
- `normalizeSceneSpec(input)` - 规范化场景规格
- `validateSceneSpec(spec)` - 验证场景规格
- `applySceneSpecEdit(spec, edit)` - 应用编辑命令
- `retimeScenes(scenes)` - 重新计算时间

架构边界：
- 禁止导入 fs、path、Express、AI、TTS、渲染服务
- 只做纯数据逻辑处理

### Step 4: 运行通过的测试
```bash
node tests/test-scene-spec.js
```
预期：输出 "scene spec tests passed"

### Step 5: 注册测试到 package.json
在 package.json 的 test 脚本中添加 `node tests/test-scene-spec.js`

### Step 6: 提交代码
```bash
git add server/services/sceneSpec.js tests/test-scene-spec.js package.json
git commit -m "新增场景规格领域服务"
```
